📜 Version 4.x History ​

[v4.7.0] - 2026-10-16 ​

🚀 Key Highlights & Developer Experience ​

Tempo v4.7.0 brings first-class Roman Numeral Date Support across parsing and formatting, full format-mask round-tripping, and canonical ISO Week-Numbering Getters (.woy and .yow) — providing developer-friendly date handling for archival publishing, epigraphy, and ISO week-calendar schedules.

NOTE

Summary of Highlights

  • Symmetric Roman Numeral Formatting & Parsing: Format any date token as a Roman numeral using {token:roman} (e.g. {yy:roman}-{mm:roman}-{dd:roman} → XXVI-X-XVI) and round-trip parse it back cleanly with custom format masks.
  • Archival & Epigraphic Date Parsing: Natively parse archival Roman date strings out-of-the-box, such as 14.X.2026, Copyright © MMXXVI, and anno domini MCMXCIV.
  • Strict Guard Pre-Filtering: Guard pre-filter prevents accidental false positives by intelligently differentiating Roman numerals from everyday lowercase English words (did, mix, civil).
  • ISO Week Getters & Tokens: Access ISO week numbering through canonical instance getters .woy (week of year) and .yow (ISO week-numbering year), complemented by {woy}, {woy:raw}, {woy:ord}, and {yow} format tokens.

🌟 New Features & Developer Guide ​

1. Roman Numeral Format Modifiers & Round-Trip Symmetry ​

Formatting dates using Roman numerals is now as simple as adding the :roman modifier to any date component:

typescript
import { Tempo } from '@magmacomputing/tempo';

const t = new Tempo('2026-10-16');

// Format with Roman numerals
const romanDate = t.format('{yy:roman}-{mm:roman}-{dd:roman}');
// 'XXVI-X-XVI'

// Parse it right back with mask symmetry!
const restored = new Tempo(romanDate, { format: '{yy:roman}-{mm:roman}-{dd:roman}' });
console.log(restored.format('iso')); // '2026-10-16'

2. Archival & Inscription Date Lexing ​

Archival dates, book copyright lines, and European-style day-RomanMonth-year strings are recognized automatically by the parser:

typescript
new Tempo('14.X.2026').format('iso'); // '2026-10-14'
new Tempo('MMXXVI').format('iso');     // '2026-01-01'
new Tempo('Copyright © MMXXVI').year;  // 2026
new Tempo('anno domini MCMXCIV').year; // 1994

The lexer introduces dedicated internal tokens:

  • Token.Rm: Roman month numbers (I through XII).
  • Token.Ry: Roman years (1–3999).
  • Token.dRy: Day-RomanMonth-Year structures (14.X.2026).
  • Token.Ryy: Archival year expressions (anno domini MMXXVI, Copyright © MMXXVI).

3. Smart Sequence Guard Validation ​

To avoid false-positive date matches during natural language parsing, Tempo includes enhanced sequence validation:

  • Valid uppercase Roman numerals (MMXXVI, XIV) and separator-adjacent Roman months (14.X.2026) are accepted.
  • Common lowercase English words that coincide with Roman letters (did, mix, civil, dim, id) are rejected by the guard filter, preventing unwanted date triggers in standard prose.

4. Canonical ISO Week-Numbering Getters (.woy & .yow) ​

Working with ISO week-numbering schedules is now clearer with dedicated instance getters:

typescript
const t = new Tempo('2026-01-01');

console.log(t.woy); // 1 (ISO week of year, 1-53)
console.log(t.yow); // 2026 (4-digit ISO week-numbering year)

// Native token formatting
t.format('{yow}-W{woy}');     // '2026-W01'
t.format('Week {woy:ord}');   // 'Week 1st'
t.format('{woy:raw}');        // '1'

Note: Legacy .ww is deprecated in favor of .woy and will be phased out in v5.0.0. Shorthand .wy and .yw remain available for internal compatibility.

5. Object Key Assertion Primitives & Disambiguation ​

Underlying utility helpers provide dedicated property assertion and narrowing primitives:

  • hasKey(obj, key, ...guards): Verifies and narrows a single property key using optional type tags ('string', 'number') or predicate functions.
  • hasKeys(obj, ...keys): Conjunction check verifying all candidate keys exist simultaneously (AND).
  • hasAnyOf(obj, ...keys): Disjunction check verifying at least one candidate key exists (OR).
  • hasNoneOf(obj, ...keys): Exclusion check verifying none of the candidate keys exist (NOT).

[v4.6.0] - 2026-10-11 ​

🚀 Key Highlights & Developer Experience ​

Tempo v4.6.0 introduces the Term Lifecycle Hooks Protocol, enabling domain plugins (such as fiscal quarters, seasons, academic calendars, and custom business cycles) to deeply integrate into Tempo's natural language parser, date arithmetic, range boundary snapping, difference calculation, and token formatting — all with zero overhead on standard ISO operations.

NOTE

Summary of Highlights

  • Term Plugins: Customize parsing, ordinal matching, step arithmetic, range boundaries, date spans (.until()/.since()), and formatting for domain terms (#).
  • Standard & Celestial Terms: Standard terms (#qtr, #szn, #zdc, #tod, #sign) and celestial plugins (#solar, #moon, #tide, #astro) natively implement lifecycle hooks for ordinals, cycle diffs, boundary snapping, and sub-attribute formatting.
  • Written & Negative Ordinals: Parse natural expressions like "first Wednesday of October" or "-2nd day of #qtr.2". Custom ordinals and number words can be registered globally or per-instance, with negative ordinals counting backward from month/cycle ends.
  • Unified Enums & Compatibility: Live enumerators are organized under Tempo.enums.*, while classic static getters remain directly accessible with deprecation notices for seamless backward compatibility.
  • Dialect Precision & Boundary Shorthands: Escaped literal braces cleanly fall back to dialect parsers, and term boundary shortcuts (start, mid, end) provide fluent range snapping.

🌟 New Features & Protocol Architecture ​

1. Well-Known Symbol Lifecycle Protocol (TermHook) ​

  • Protected Protocol Symbols: Protects term hooks against naming collisions and dual-package hazards using cross-realm well-known symbols (Symbol.for('magmacomputing/tempo/term/...')):
    • [TermHook.parse]: Intercepts explicit #term expressions (e.g. new Tempo('#fiscal.q1')).
    • [TermHook.ordinal]: Powers anchored ordinal expressions (e.g. Tempo.from('3rd day of #sprint.2', { anchor })).
    • [TermHook.step]: Enables stepping arithmetic via dictionary mutations (t.add({ '#qtr': 1 }), t.sub({ '#qtr': 1 })).
    • [TermHook.bound]: Snaps boundaries for custom term periods (t.set({ '#term': 'start' | 'mid' | 'end' }), t.set({ start: '#term' }), and t.set('#term.mid')).
    • [TermHook.diff]: Calculates differences in term units (t1.until(t2, '#term'), t1.since(t2, '#term')).
    • [TermHook.format]: Dispatches custom term format tokens (e.g. t.format('{#academic}'), t.format('{#academic:upper}')).

2. Native Term Units in .until() & .since() ​

  • Custom Term Differences: Tempo.Unit and Tempo.Until now accept custom term units (#${string}), providing full IDE autocompletion and compile-time type safety when calculating spans between dates:
    typescript
    const quartersRemaining = t1.until(t2, '#quarter');
const elapsed = t2.since(t1, '#fiscal');

3. Standard & Celestial Terms Lifecycle Integration ​

  • Natural Range Ordinals: Standard terms (#qtr, #szn, #zdc) implement [TermHook.ordinal], enabling natural ordinal offset expressions like Tempo.from('3rd day of #qtr.2', { anchor }), Tempo.from('-2nd day of #qtr.2', { anchor }), and Tempo.from('last day of #szn.summer', { anchor }) with strict cycle boundary guarding.
  • Term Unit Differences (.until() & .since()): Standard terms implement [TermHook.diff] via resolveRangeDiff(), calculating elapsed cycle intervals:
    typescript
    t1.until(t2, '#qtr'); // 3
t2.since(t1, '#qtr'); // "-3 #qtr"
  • Hierarchical Token Formatting: Standard terms implement [TermHook.format] via resolveRangeFormat(), resolving top-level keys ({#qtr} → "Q2"), descriptive scopes ({#quarter} → "Second Quarter"), and arbitrary nested sub-attributes ({#qtr.label}, {#szn.symbol}, {#zdc.emoji}, {#sign.animal}, {#tod.hour}) with automatic modifier support ({#qtr.label:upper}).
  • Shared Plugin SDK Utilities: Exported resolveRangeOrdinal, resolveRangeDiff, and resolveRangeFormat via @magmacomputing/tempo/plugin/sdk.
  • Celestial Plugin Support: Celestial terms (#solar, #moon, #tide, #astro) implement lifecycle hooks for boundary snapping, synodic stepping, interval calculations, and astrological/solar formatting.

4. Unified Tempo.enums Namespace & Extensible Ordinals ​

  • Unified Tempo.enums Accessor: Consolidates all live enum dictionaries under Tempo.enums.*. For 100% backward compatibility with existing v4 call sites, legacy static getters on Tempo (ELEMENT, FORMAT, NUMBER, ORDINAL, TIMEZONE, MONTH_DAY, MODE, CACHE, LIMIT) remain available directly on the Tempo class with @deprecated notices.
  • Native Written Word Ordinals: Natively parses natural ordinal expressions like "first Wednesday of October", "second day of next month", "tenth Friday of the year", and "last day of May".
  • ORDINAL Enumerator: Exported through @magmacomputing/tempo/enums and accessible via Tempo.enums.ORDINAL, mapping words to numeric offsets (current: 0, first: 1 through tenth: 10, last: -1).
  • Dynamic & Per-Instance Extensibility: Configure custom ordinals globally via Tempo.init({ registry: { ordinals: { ... } } }) or per-instance via constructor options (new Tempo('...', { registry: { ordinals: { ... } } })). Per-instance ordinals are dynamically compiled into instance regexes without polluting global state.
  • Term Plugin Integration: Directly leveraged by [TermHook.ordinal] for resolving custom term offsets (such as sprint days or fiscal cycles).

5. Shorthand Boundary Mutations ​

  • Direct Snap Shorthands: Term boundary selection (start, mid, end) can be expressed directly via dictionary mutations (t.set({ '#term': 'start' | 'mid' | 'end' }), t.set({ start: '#term' })) or property shorthand (t.set('#term.start'), t.set('#term.mid'), t.set('#term.end')).

6. Dialect Mask Precision & Engine Optimization ​

  • Dialect Literal Brace Escaping: Added hasNativeFormatBraces to strip dialect-specific escaped literals ([...] in Moment/Day.js, '...' in LDML/Luxon) before testing for native {token} masks, ensuring masks with escaped braces cleanly fall back to external dialect formatters.
  • Isolated # Sigil Guards: Hook dispatch occurs strictly for domain term expressions (#), ensuring everyday ISO date parsing, standard formatting, and core unit arithmetic bypass hook execution paths.
  • Complete Backward Compatibility: Existing term plugins continue to function without any modifications.

  • Fast Factory Getters: Access cached constructor factories for dtf() (DateTime), rtf() (RelativeTime), lf() (List), and nf() (Number).

3. Advanced Format & Translation Capabilities ​

  • Hierarchical Translations: Formatting strings support nested tokens for namespaced plugin keys (e.g. {geo.sphere:locale}).
  • Combined Timezone Offset Styles: Enhanced time-zone offset formatting modifiers like {offset:iso}, {offset:gmt}, and composite modifiers like {tz:offset:short}.

    typescript

const clockStream = new Reactive<string>();

// Subscribe with automatic cleanup via TC39 explicit resource management:
{
  using sub = clockStream.on((iso) => console.log('Tick:', iso));

  • Async Iteration: Consume events naturally using standard for await (const tick of clockStream) loops.

    typescript

const config = cast<CustomConfig>(rawPayload);

  • Parse structured date strings using Tempo's standard braced token format:
    typescript
    const t = new Tempo('24-10-2026', { format: '{dd}-{mm}-{yyyy}' });
const t2 = Tempo.from('2026/10/24 15:30:45', { format: '{yyyy}/{mm}/{dd} {hh}:{mi}:{ss}' });

    typescript

  format: '{*} [{yyyy}-{mm}-{dd} {hh}:{mi}] {*}'

});

[v4.1.0] - 2026-09-04 ​

🚀 Key Highlights & Architectural Enhancements ​

Tempo v4.1.0 expands enterprise configuration governance and developer ergonomics with Remote & Cascading Configuration Resolution ("extends"), a dedicated pluginOptions Configuration Slot, and Overloaded Tempo.create() with Deterministic Resource Disposal (TC39 using).

🌟 New Features & Improvements ​

1. Remote & Cascading Configuration Resolution (resolveConfig) ​

  • Remote URL Config Fetching: Enhanced resolveConfig() and Tempo.bootstrap() to fetch tempo.config.jsonc and tempo.config.json over http:// and https:// URLs (including http://localhost:... or http://127.0.0.1:... for dev servers, container environments, and central governance APIs).
  • file:// URL Support: Added native support for file:// URLs in Node.js environments via fileURLToPath.
  • Cascading Inheritance ("extends"): Introduced recursive "extends" resolution in configuration files (string URL/path or array of URLs/paths). Parent configurations are resolved and merged under child local overrides.
  • Security Boundaries & Loop Protection: HTTP requests are bounded by a 3-second timeout and 128KB payload size cap to prevent hangs and DoS attacks. Remote configs are restricted to static data-only JSON/JSONC payloads. Circular inheritance is detected and prevented.

2. Dedicated pluginOptions Configuration Slot ​

  • Introduced pluginOptions?: Record<string, any> across BaseOptions, Discovery, and Config.
  • Enforces clean architectural separation:
    • plugins: Strictly reserved for executable code registration (plugins, terms, modules).
    • pluginOptions: Dedicated dictionary holding serializable runtime options and defaults for plugins.
  • Deep, recursive namespace merging across extends inheritance layers.
  • Supplying plain configuration dictionaries directly under plugins is marked @deprecated in favor of pluginOptions.

3. Overloaded Tempo.create() & Deterministic Resource Disposal ​

  • Explicit Resource Management (TC39 using): Tempo.create() returns SandboxTempo subclasses that implement the TC39 Disposable protocol (Symbol.dispose) and expose an isDisposed getter. Disposing a sandbox clears its discovery slot from globalThis and cleans up internal registry state (ClassStates).
  • Scoped Callback Mode (Tempo.create(fn) / Tempo.create(options, fn)): Overloaded Tempo.create() to accept an execution callback, automatically disposing the ephemeral sandbox upon completion (supporting both synchronous results and async Promises via try...finally).
  • Native using Block Scoping: Full support for TypeScript 5.2+ block-scoped disposable sandboxes: { using sb = Tempo.create({ ... }); ... }.

4. Architectural Separation of extends and plugins ​

  • extends: Strictly reserved for configuration inheritance via URLs or file paths (string | string[]), mirroring tsconfig.json and ESLint conventions.
  • plugins: Dedicated for registering executable plugins and terms ((Plugin | Term)[]).
  • Tempo.use() & Deprecation of Tempo.extend(): Standardized Tempo.use(...) as the runtime registration method. Marked Tempo.extend() as @deprecated Use Tempo.use(...) instead. while preserving backwards compatibility.

🐛 Bug Fixes ​

  • Sandbox Symbol.dispose Global State Leakage: Fixed a critical bug where invoking [Symbol.dispose]() on a sandbox class (e.g., via the TC39 using keyword or scoped callback mode) inherited Tempo[Symbol.dispose]() via the prototype chain and inadvertently executed Tempo.init(), wiping the global library configuration and registered plugins. Sandboxed classes now implement an isolated [Symbol.dispose]() that strictly cleans up local sandbox state and discovery slots without mutating global defaults.

[v4.0.0] - 2026-08-27 ​

🚀 Key Highlights & Paradigm Shifts ​

Tempo v4.0.0 is a major architectural milestone introducing Dynamic Functional Context (DFC), a 100% Open-Source Community Core, zero-await Synchronous JSONC Config Discovery, standardized Plugin SDK Facade, and unified {Term: Value} Mutation Payloads.

🚨 Major Breaking Changes ​

  • 100% Open-Source Community Core: Completely removed commercial licensing enforcement, JWT verification, JWS claims validation, domain-locking, and premium plugin gating (license.manager.ts, license.validator.ts, Tempo.license, validateLicenseState, LICENSE enum, and $updateScopeStatus).
  • Commercial Package Decoupling: Relocated all enterprise licensing hooks and commercial plugin management to the @magmacomputing/tempo-pro wrapper package.
  • Config Auto-Discovery Modernization: Dropped .cjs configuration discovery support in favor of modern ES-preferred module extensions (.mts, .ts, .mjs, .js, .jsonc, .json).
  • Tempo.ready() Return Signature: Simplified Tempo.ready() return value to a static 'none' status for community core compatibility.
  • Configuration Namespace Enforcement: Fully excised legacy root-level property access that was deprecated during v3.x.
    • formats configuration key has been entirely removed from top-level Options and Discovery. Use registry: { formats: ... } instead.
    • numbers configuration key has been entirely removed from top-level Options. Use registry: { numbers: ... } instead.

🌟 New Features & Architectural Modernizations ​

1. Dynamic Functional Context (DFC) & Options Evaluation ​

  • Upgraded BaseOptions and Tempo options (timeZone, locale, calendar, sphere) to support Evaluable<T> suppliers (T | (() => T)).
  • Context options are dynamically evaluated on a per-request basis without requiring instantiation or re-building configuration state, perfect for multi-tenant applications (e.g., dynamic request headers or per-tenant session resolvers).

2. Synchronous JSON & JSONC Config Discovery (resolveConfigSync) ​

  • Introduced zero-await static startup configuration discovery (resolveConfigSync()) utilizing parseJSONC for .jsonc and .json files.
  • ESM and TypeScript config modules (.mts, .ts, .mjs, .js) continue to utilize the asynchronous resolveConfig() path.
  • Automatically executed inside Tempo's static { ... } initialization block at module load time.

3. Standardized Plugin SDK Facade (@magmacomputing/tempo/plugin/sdk) ​

  • Standardized plugin development on @magmacomputing/tempo/plugin/sdk, replacing legacy plugin-api imports.
  • Exposes definePlugin, defineTerm, defineModule, defineNamespace, defineRange, and internal evaluation utilities via a single, CDN-friendly facade.

4. Expanded Utility Stack Exports (@magmacomputing/tempo/library) ​

  • Re-exported core evaluation and runtime primitives (Evaluable, AsyncEvaluable, evaluate, evaluateAsync, evaluateConfig, evaluateConfigAsync, dynamicProxy, Pledge, cipher, webToken, enumify) via the @magmacomputing/tempo/library export surface for downstream plugins and custom extensions.

5. API Standardization for Boundary & Mutation Payloads ({Term: Value}) ​

  • Standardized mutation object signatures across .set(), .add(), and plugin payloads to follow the unified {Term: Value} pattern (e.g., .set({ year: 'start' }), .set({ month: 'end' }), .set({ '#qtr': 1 })).
  • Legacy positional syntax (e.g., .set({ start: 'year' })) remains supported transparently for backwards compatibility.

🗑️ API Removals & Cleanups ​

  • Removed Static Accessors: Removed Tempo.formats accessor; use Tempo.registry.formats instead.
  • Removed Deprecated Subpaths: Removed #tempo/license export mapping.
