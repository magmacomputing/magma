# 📜 Version 4.x History

## [v4.5.1] - 2026-10-05

### 🚀 Key Highlights & Developer Experience

Tempo v4.5.1 focuses on **Seamless Dynamic Plugin Loading & Sandbox Resilience**, ensuring interactive REPLs, browser playgrounds, and dynamically bundled micro-frontends can load and register plugins on-the-fly without friction.

---

### 🌟 Improvements & Fixes

#### 1. Dynamic Plugin Registry Resilience
- **Late-Loaded Plugin Support**: When loading plugins asynchronously via `import()` inside dynamic environments or browser sandboxes, internal plugin tables are protected with extensible metadata symbols.
- **Copy-on-Write Registrations**: Registering terms and plugins after initialization safely falls back to copy-on-write updates on non-extensible registry arrays and `pluginsDb` objects when the parent container permits reassignment (replacing `pluginsDb` can still throw a `TypeError` if the owning state itself is frozen).

---

## [v4.5.0] - 2026-10-02

### 🚀 Key Highlights & Architectural Enhancements

Tempo v4.5.0 introduces the **Structured `t.intl` Namespace (`intl.info` & `intl.locale`)**, the high-performance **`Tempo.intl` Formatter Hub**, and **Hierarchical Translation Token Support**.

---

### 🌟 New Features & Improvements

#### 1. Structured `t.intl` Sub-Namespace (`intl.info` & `intl.locale`)
- **Clean Regional Metadata (`t.intl.info`)**: Regional insights are now cleanly grouped under `.info`, giving direct access to frozen locale characteristics:
  ```typescript
  const t = new Tempo('now', { locale: 'en-AU' });
  console.log(t.intl.info.firstDay);        // 1 (Monday)
  console.log(t.intl.info.weekend);         // [6, 7] (Saturday, Sunday)
  console.log(t.intl.info.hourCycle);       // 'h12'
  console.log(t.intl.info.direction);       // 'ltr'
  console.log(t.intl.info.numberingSystem); // 'latn'
  ```
- **Native Locale Inspection (`t.intl.locale`)**: Inspect the active `Intl.Locale` instance directly.
- **Backward Compatibility**: Top-level convenience properties (like `t.intl.firstDay` and `t.intl.region`) remain fully supported throughout the v4.x lifecycle with gentle deprecation notices.

#### 2. `Tempo.intl` Formatter Hub
- **Instant Pre-Bound Formatters**: Perform standard internationalization formatting directly through static helpers without manually configuring `Intl.*` classes:
  ```typescript
  // Relative Time Formatting
  Tempo.intl.relativeTime(-2, 'days'); // "2 days ago"
  
  // Natural List Formatting
  Tempo.intl.list(['Sydney', 'Tokyo', 'London']); // "Sydney, Tokyo, and London"
  
  // Number & Currency Formatting
  Tempo.intl.number(1234567.89); // "1,234,567.89"
  ```
- **Fast Factory Getters**: Access cached constructor factories for `dtf()` (DateTime), `rtf()` (RelativeTime), `lf()` (List), and `nf()` (Number).

#### 3. Advanced Format & Translation Capabilities
- **Hierarchical Translations**: Formatting strings support nested tokens for namespaced plugin keys (e.g. `{geo.sphere:locale}`).
- **Combined Timezone Offset Styles**: Enhanced time-zone offset formatting modifiers like `{offset:iso}`, `{offset:gmt}`, and composite modifiers like `{tz:offset:short}`.

## [v4.4.4] - 2026-09-30

### 🚀 Key Highlights & Architectural Enhancements

Tempo v4.4.4 introduces the **Reactive Stream Engine (`Reactive<T>`)** in the utility library, ergonomic **Type Casting Helpers (`cast<T>()`)**, and explicit **`Tempo.Interval` Types**.

---

### 🌟 New Features & Improvements

#### 1. Reactive Stream Engine (`Reactive<T>`)
- **Lightweight Event Streaming**: Exported via `@magmacomputing/tempo/library` and the Plugin SDK, `Reactive<T>` offers push/pull streaming with zero external dependencies:
  ```typescript
  import { Reactive } from '@magmacomputing/tempo/library';

  const clockStream = new Reactive<string>();

  // Subscribe with automatic cleanup via TC39 explicit resource management:
  {
    using sub = clockStream.on((iso) => console.log('Tick:', iso));
    clockStream.cast(new Tempo().iso);
  } // Subscription automatically unsubscribes when exiting block!
  ```
- **Async Iteration**: Consume events naturally using standard `for await (const tick of clockStream)` loops.
- **Multicast Fan-Out**: High-performance $O(1)$ broadcasting across all active push subscribers and async waiters via `stream.cast(value)`.

#### 2. Ergonomic Type Casting (`cast<T>()`)
- Replaces awkward `(value as unknown as TargetType)` double-assertions with a clean runtime and compile-time casting helper:
  ```typescript
  import { cast } from '@magmacomputing/tempo/library';
  const config = cast<CustomConfig>(rawPayload);
  ```

## [v4.4.1] - 2026-09-20

### 🚀 Key Highlights & Architectural Enhancements

Tempo v4.4.1 introduces **Braced Format Mask Parsing (`{format: '...'}`) & Wildcards (`{*}`)**, **`Evaluable<T>` dynamic format & dialect configuration**, and official launch integration for **`@magmacomputing/tempo-plugin-dialects`**.

---

### 🌟 New Features & Improvements

#### 1. Core Braced Format Mask Parsing & Wildcard Matching
- Parse structured date strings using Tempo's standard braced token format:
  ```typescript
  const t = new Tempo('24-10-2026', { format: '{dd}-{mm}-{yyyy}' });
  const t2 = Tempo.from('2026/10/24 15:30:45', { format: '{yyyy}/{mm}/{dd} {hh}:{mi}:{ss}' });
  ```
- **Candidate Format Arrays**: Supply multiple candidate masks to match the first matching format:
  ```typescript
  const t = new Tempo(input, { format: ['{yyyy}-{mm}-{dd}', '{dd}/{mm}/{yyyy}'] });
  ```
- **Wildcard Token `{*}`**: Skip arbitrary substrings or log prefixes without complex regular expressions:
  ```typescript
  const t = new Tempo('Log entry [2026-10-24 15:30] server-01', {
    format: '{*} [{yyyy}-{mm}-{dd} {hh}:{mi}] {*}'
  });
  ```
- **Actionable Dialect Guidance**: Passing unbraced masks (e.g. `'yyyy-MM-dd'`) without the dialects plugin throws clear guidance directing users to `@magmacomputing/tempo-plugin-dialects`.

#### 2. Dynamic `Evaluable<T>` Format & Dialect Resolution
- Configuration and call-site options for `format` and `dialect` now accept dynamic resolver functions (`() => string`), seamlessly evaluated at runtime via `evaluate()`:
  ```typescript
  const t = new Tempo(input, {
    format: () => getUserPreferredFormat()
  });
  ```

#### 3. Dialects Plugin Integration (`@magmacomputing/tempo-plugin-dialects`)
- Official v1.0.0 release of the Dialects plugin enabling Unicode LDML (Luxon/date-fns), POSIX strftime, and Moment.js mask translation, formatting, and parsing.

## [v4.4.0] - 2026-09-18

### 🚀 Key Highlights & Architectural Enhancements

Tempo v4.4.0 introduces **Order-Independent Plugin Auto-Installation (`/install`)** and global pending queues, bringing zero-boilerplate side-effect imports for browser scripts, quick prototypes, and interactive REPLs.

---

### 🌟 New Features & Improvements

#### 1. Zero-Boilerplate Side-Effect Imports (`/install`)
- Official and community plugins can now be installed with a single import statement:
  ```typescript
  import '@magmacomputing/tempo-plugin-geo/install';
  import '@magmacomputing/tempo-plugin-ai/install';
  ```
- **Order-Independent Registration (`$pendingAutoInstalls`)**: If a bundler or browser module loader evaluates a plugin's `/install` subpath *before* `{ Tempo }` has finished initializing, registrations are safely buffered in an ambient queue and automatically drained as soon as Tempo boots.
- **Tree-Shaking Preserved**: Standard imports (`import { GeoPlugin } from '@magmacomputing/tempo-plugin-geo'`) retain 100% tree-shakeability with zero automatic side-effects.

## [v4.3.0] - 2026-09-16

### 🚀 Key Highlights & Architectural Enhancements

Tempo v4.3.0 brings **Colocated Plugin Options & Hybrid Factories**, deep **`Intl.LocaleInfo` Regional Calendar Context**, and a direct **Native Temporal Gateway (`t.zdt`)**.

---

### 🌟 New Features & Improvements

#### 1. Colocated Plugin Options & Callable Factories
- **Vite / Rollup Style Factory Invocations**: Plugins constructed via `definePlugin` now function as hybrid callable factories. Pass options directly at call-site:
  ```typescript
  Tempo.init({
    plugins: [
      TickerPlugin({ interval: 1000 }),
      [GeoPlugin, { timeout: 5000 }] // Tuple syntax also fully supported!
    ]
  });
  ```
- **Uncalled Plugins Retained**: Passing uncalled plugins (`plugins: [CelestialPlugin]`) continues to work seamlessly without breaking changes.

#### 2. `Intl.Locale` Info & Culturally Authentic Calendars (`t.intl`)
- **First-Class Regional Metadata**: Direct access via `t.intl` (and `Tempo.intl`) providing frozen regional insights (`firstDay`, `weekend`, `hourCycle`, `direction`, `numberingSystem`), alongside `t.intl.locale` for native `Intl.Locale` inspection.
- **Adaptive Week Arithmetic (`localeInfo: true`)**: With `localeInfo: true`, operations like `t.set({ week: 'start' })` automatically align to the locale's culturally authentic first day (e.g. Sunday in the US, Monday in the UK, Saturday in Saudi Arabia).
- **Dedicated ISO Invariants**: Use `isoWeek` and `wy` (`t.set({ isoWeek: 'start' })`) to guarantee Monday-start snapping regardless of locale settings.
- **Localized Format Tokens**: Added `{dow:locale}`, `{hh:locale}`, `{time:locale}`, and localized numeral formatting (`{yyyy:locale}` producing `٢٠٢٦` in Arabic locales).

#### 3. Direct Native Temporal Gateway (`t.zdt`)
- Direct read-only getter `t.zdt` exposing the underlying `Temporal.ZonedDateTime` instance for zero-overhead access to native Temporal properties (`daysInMonth`, `inLeapYear`, `offset`, `hoursInDay`) without method ceremony.

#### 4. Day-of-Year Property & Token (`t.doy`, `{doy}`)
- Direct `t.doy` accessor (`1..366`) and formatting token `{doy}` with width padding support (`{doy:3}`).

## [v4.1.0] - 2026-09-04

### 🚀 Key Highlights & Architectural Enhancements

Tempo v4.1.0 expands enterprise configuration governance and developer ergonomics with **Remote & Cascading Configuration Resolution (`"extends"`)**, a dedicated **`pluginOptions` Configuration Slot**, and **Overloaded `Tempo.create()` with Deterministic Resource Disposal (TC39 `using`)**.

---

### 🌟 New Features & Improvements

#### 1. Remote & Cascading Configuration Resolution (`resolveConfig`)
- **Remote URL Config Fetching**: Enhanced `resolveConfig()` and `Tempo.bootstrap()` to fetch `tempo.config.jsonc` and `tempo.config.json` over `http://` and `https://` URLs (including `http://localhost:...` or `http://127.0.0.1:...` for dev servers, container environments, and central governance APIs).
- **`file://` URL Support**: Added native support for `file://` URLs in Node.js environments via `fileURLToPath`.
- **Cascading Inheritance (`"extends"`)**: Introduced recursive `"extends"` resolution in configuration files (string URL/path or array of URLs/paths). Parent configurations are resolved and merged under child local overrides.
- **Security Boundaries & Loop Protection**: HTTP requests are bounded by a 3-second timeout and 128KB payload size cap to prevent hangs and DoS attacks. Remote configs are restricted to static data-only JSON/JSONC payloads. Circular inheritance is detected and prevented.

#### 2. Dedicated `pluginOptions` Configuration Slot
- Introduced `pluginOptions?: Record<string, any>` across `BaseOptions`, `Discovery`, and `Config`.
- Enforces clean architectural separation:
  - `plugins`: Strictly reserved for executable code registration (plugins, terms, modules).
  - `pluginOptions`: Dedicated dictionary holding serializable runtime options and defaults for plugins.
- Deep, recursive namespace merging across `extends` inheritance layers.
- Supplying plain configuration dictionaries directly under `plugins` is marked `@deprecated` in favor of `pluginOptions`.

#### 3. Overloaded `Tempo.create()` & Deterministic Resource Disposal
- **Explicit Resource Management (TC39 `using`)**: `Tempo.create()` returns `SandboxTempo` subclasses that implement the TC39 `Disposable` protocol (`Symbol.dispose`) and expose an `isDisposed` getter. Disposing a sandbox clears its discovery slot from `globalThis` and cleans up internal registry state (`ClassStates`).
- **Scoped Callback Mode (`Tempo.create(fn)` / `Tempo.create(options, fn)`)**: Overloaded `Tempo.create()` to accept an execution callback, automatically disposing the ephemeral sandbox upon completion (supporting both synchronous results and async Promises via `try...finally`).
- **Native `using` Block Scoping**: Full support for TypeScript 5.2+ block-scoped disposable sandboxes: `{ using sb = Tempo.create({ ... }); ... }`.

#### 4. Architectural Separation of `extends` and `plugins`
- **`extends`**: Strictly reserved for configuration inheritance via URLs or file paths (`string | string[]`), mirroring `tsconfig.json` and ESLint conventions.
- **`plugins`**: Dedicated for registering executable plugins and terms (`(Plugin | Term)[]`).
- **`Tempo.use()` & Deprecation of `Tempo.extend()`**: Standardized `Tempo.use(...)` as the runtime registration method. Marked `Tempo.extend()` as `@deprecated Use Tempo.use(...) instead.` while preserving backwards compatibility.

---

### 🐛 Bug Fixes

- **Sandbox `Symbol.dispose` Global State Leakage**: Fixed a critical bug where invoking `[Symbol.dispose]()` on a sandbox class (e.g., via the TC39 `using` keyword or scoped callback mode) inherited `Tempo[Symbol.dispose]()` via the prototype chain and inadvertently executed `Tempo.init()`, wiping the global library configuration and registered plugins. Sandboxed classes now implement an isolated `[Symbol.dispose]()` that strictly cleans up local sandbox state and discovery slots without mutating global defaults.

---

## [v4.0.0] - 2026-08-27

### 🚀 Key Highlights & Paradigm Shifts

Tempo v4.0.0 is a major architectural milestone introducing **Dynamic Functional Context (DFC)**, a **100% Open-Source Community Core**, zero-`await` **Synchronous JSONC Config Discovery**, standardized **Plugin SDK Facade**, and unified **`{Term: Value}` Mutation Payloads**.

---

### 🚨 Major Breaking Changes

- **100% Open-Source Community Core**: Completely removed commercial licensing enforcement, JWT verification, JWS claims validation, domain-locking, and premium plugin gating (`license.manager.ts`, `license.validator.ts`, `Tempo.license`, `validateLicenseState`, `LICENSE` enum, and `$updateScopeStatus`).
- **Commercial Package Decoupling**: Relocated all enterprise licensing hooks and commercial plugin management to the `@magmacomputing/tempo-pro` wrapper package.
- **Config Auto-Discovery Modernization**: Dropped `.cjs` configuration discovery support in favor of modern ES-preferred module extensions (`.mts`, `.ts`, `.mjs`, `.js`, `.jsonc`, `.json`).
- **`Tempo.ready()` Return Signature**: Simplified `Tempo.ready()` return value to a static `'none'` status for community core compatibility.
- **Configuration Namespace Enforcement**: Fully excised legacy root-level property access that was deprecated during `v3.x`.
  - `formats` configuration key has been entirely removed from top-level `Options` and `Discovery`. Use `registry: { formats: ... }` instead.
  - `numbers` configuration key has been entirely removed from top-level `Options`. Use `registry: { numbers: ... }` instead.

---

### 🌟 New Features & Architectural Modernizations

#### 1. Dynamic Functional Context (DFC) & Options Evaluation
- Upgraded `BaseOptions` and `Tempo` options (`timeZone`, `locale`, `calendar`, `sphere`) to support `Evaluable<T>` suppliers (`T | (() => T)`).
- Context options are dynamically evaluated on a per-request basis without requiring instantiation or re-building configuration state, perfect for multi-tenant applications (e.g., dynamic request headers or per-tenant session resolvers).

#### 2. Synchronous JSON & JSONC Config Discovery (`resolveConfigSync`)
- Introduced zero-`await` static startup configuration discovery (`resolveConfigSync()`) utilizing `parseJSONC` for `.jsonc` and `.json` files.
- ESM and TypeScript config modules (`.mts`, `.ts`, `.mjs`, `.js`) continue to utilize the asynchronous `resolveConfig()` path.
- Automatically executed inside `Tempo`'s `static { ... }` initialization block at module load time.

#### 3. Standardized Plugin SDK Facade (`@magmacomputing/tempo/plugin/sdk`)
- Standardized plugin development on `@magmacomputing/tempo/plugin/sdk`, replacing legacy `plugin-api` imports.
- Exposes `definePlugin`, `defineTerm`, `defineModule`, `defineNamespace`, `defineRange`, and internal evaluation utilities via a single, CDN-friendly facade.

#### 4. Expanded Utility Stack Exports (`@magmacomputing/tempo/library`)
- Re-exported core evaluation and runtime primitives (`Evaluable`, `AsyncEvaluable`, `evaluate`, `evaluateAsync`, `evaluateConfig`, `evaluateConfigAsync`, `dynamicProxy`, `Pledge`, `cipher`, `webToken`, `enumify`) via the `@magmacomputing/tempo/library` export surface for downstream plugins and custom extensions.

#### 5. API Standardization for Boundary & Mutation Payloads (`{Term: Value}`)
- Standardized mutation object signatures across `.set()`, `.add()`, and plugin payloads to follow the unified `{Term: Value}` pattern (e.g., `.set({ year: 'start' })`, `.set({ month: 'end' })`, `.set({ '#qtr': 1 })`).
- Legacy positional syntax (e.g., `.set({ start: 'year' })`) remains supported transparently for backwards compatibility.

---

### 🗑️ API Removals & Cleanups

- **Removed Static Accessors**: Removed `Tempo.formats` accessor; use `Tempo.registry.formats` instead.
- **Removed Deprecated Subpaths**: Removed `#tempo/license` export mapping.
